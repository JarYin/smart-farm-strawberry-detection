# Smart Farm Autonomous Robot — ระบบตรวจจับวัชพืชและสั่งพ่นยาอัตโนมัติ

ระบบ Edge AI ที่ใช้กล้องตรวจจับพืชเป้าหมาย (สตรอว์เบอร์รี) และวัชพืชแบบเรียลไทม์
เมื่อพบวัชพืชจะสั่งเปิดปั๊มพ่นยาเฉพาะจุดผ่านโมดูลรีเลย์ ทำงานบน Raspberry Pi 4

```
กล้อง OV5647  ->  ย่อภาพ 320x320  ->  YOLOv8 Nano (TFLite)  ->  ตัดสินใจ  ->  Relay  ->  ปั๊มพ่นยา
   640x480          letterbox            7-10 FPS บน Pi 4        ROI+ยืนยัน      GPIO17
```

- **พบสตรอว์เบอร์รี** → ปล่อยผ่าน ไม่พ่น
- **พบวัชพืช** → ยืนยันหลายเฟรม → เปิดปั๊มพ่นเฉพาะจุด
- **วัชพืชขึ้นชิดพืชหลัก** → งดพ่น เพื่อไม่ให้สารเคมีโดนพืชผล

> ### 🎤 คุณกำลังอยู่บน branch `prototype-v1`

## 0. โหมดต้นแบบนำเสนอผลงาน (prototype-v1)

### สั่งรันสาธิต

```powershell
python -m src.main                       # ใช้ค่าใน config.yaml ของ branch นี้ (โหมดสีอยู่แล้ว)
python -m src.main --backend color       # บังคับโหมดสี ไม่ว่า config จะตั้งไว้อย่างไร
python -m src.main --backend auto        # สลับกลับไปใช้โมเดล AI ตัวจริงชั่วคราว
```

ยกแผ่นสีเข้าไปใน **กรอบ LASER ZONE** (กรอบฟ้าครึ่งล่างของภาพ) แล้วดูแผง HUD มุมบนซ้าย
ที่บรรทัด `LASER ON/OFF` — นอกกรอบนั้นระบบถือว่าลำแสงยิงไปไม่ถึง จึงไม่นับในการตัดสินใจ

### ทำงานอย่างไร

```
กล้อง 640x480 -> เบลอลด noise -> แปลงเป็น HSV -> ทำ mask ทีละสี -> หา contour -> กรอบ
                                                                                    |
                    เลเซอร์ <- Relay GPIO17 <- เครื่องสถานะ + ยืนยันหลายเฟรม <- ตรรกะเดิม
```

ทำไมต้อง **HSV** ไม่ใช่ RGB: HSV แยก "เนื้อสี (H)" ออกจาก "ความสว่าง (V)" ได้
แผ่นสีแดงใบเดิมใต้ไฟสว่างกับในเงา จะมีค่า H ใกล้เคียงกันแม้ V ต่างกันมาก
ถ้าเทียบค่า RGB ตรงๆ เงาที่พาดผ่านแผ่นสีจะทำให้ตรวจไม่เจอทันที

ค่าความเชื่อมั่นที่คืนออกมาคือ **fill ratio** = พื้นที่สีจริง ÷ พื้นที่กรอบสี่เหลี่ยม
(แผ่นสี่เหลี่ยม ~0.95 | วงกลม ~0.79 | ริ้วสี/เงาสะท้อน ต่ำกว่า 0.5) ค่านี้อยู่ในช่วง 0-1
เหมือนคะแนนของโมเดล AI จึงไหลผ่านเกณฑ์ `model.conf` และตรรกะเดิมได้โดยไม่ต้องแก้อะไร

### ตารางการตัดสินใจ

ทั้งหมดนี้มาจาก `classes.inverse_mode: true` (กฎ "ไม่เจออะไรเลยก็ยิง" พึ่งโหมดนี้):

| ในเขต LASER ZONE | ผลลัพธ์ | กรอบที่รายงานใน log |
|---|---|---|
| พบสีแดง (จะมีสีเขียวด้วยหรือไม่ก็ตาม) | **ไม่ยิง** — งดทั้งเขต | กรอบสีเหลือง `HOLD` |
| ไม่พบแดง + พบสีเขียว | **ยิง** | กรอบสีเขียวจริง `FIRE` |
| ไม่พบอะไรเลย | **ยิง** | กรอบสังเคราะห์ `non-crop-area` คลุมทั้งเขต |

ความปลอดภัยของพืชหลักมาก่อนเสมอ — เจอสีแดงในเขตเมื่อไหร่ งดยิงทั้งเขตทันที
แม้จะมีสีเขียวอยู่ข้างๆ ก็ตาม

### จูนค่าสีให้เข้ากับแสงหน้างาน (ทำก่อนขึ้นนำเสนอเสมอ)

ค่าสีที่กล้องจับได้ขึ้นกับแสงมาก แผ่นสีใบเดียวกันใต้ไฟ LED ขาวกับใต้ไฟเหลือง
ในห้องประชุมให้ค่า HSV ต่างกันชัดเจน ไปถึงสถานที่จริงแล้วจูน 2 นาทีด้วย:

```powershell
python tools\color_tune.py                # จูนสีแดง (มีแถบเลื่อนให้ลากสดๆ)
python tools\color_tune.py --band green   # จูนสีเขียว (หรือกด b ระหว่างรัน)
```

ลำดับการจูนที่เร็วที่สุด — ดูหน้าต่าง `mask` (ขาว = ผ่านเกณฑ์) เป็นหลัก:

1. ให้แผ่นสีขึ้นเป็นก้อน **ขาวทึบ ไม่มีรู**
2. ค่อยๆ เพิ่ม `S min` จนพื้นหลัง/เงา/ผิวมือ **ดำสนิท** แต่แผ่นสียังขาวอยู่
3. เพิ่ม `V min` ถ้ามุมมืดของภาพยังขาวหลอกอยู่
4. บีบ `H` ให้แคบที่สุดเท่าที่แผ่นสียังขาวครบทั้งแผ่น

กด `q` เพื่อออก โปรแกรมจะพิมพ์ค่าที่ได้ในรูปแบบ YAML ให้คัดลอกไปวางใน `config.yaml`
กด `p` แล้วคลิกบนภาพเพื่ออ่านค่า H/S/V ของจุดนั้นตรงๆ ก็ได้

รายละเอียดโครงสร้างโฟลเดอร์และคำแนะนำเรื่องจำนวนภาพ อ่านที่ [datasets/README.md](datasets/README.md)


## 5. ตรรกะการตัดสินใจพ่น

ถ้าเขียนแบบง่ายที่สุดคือ "เจอวัชพืช = เปิดปั๊ม" ซึ่งใช้งานจริงไม่ได้
[src/logic.py](src/logic.py) จึงมีกลไก 5 ชั้นซ้อนกัน:

**1. เกณฑ์ความเชื่อมั่นรายคลาส**
ตั้งเกณฑ์ของวัชพืชให้สูงกว่าพืชเป้าหมาย เพราะการพ่นผิดมีต้นทุนสูงกว่าการไม่พ่น

**2. ขอบเขตหัวฉีด (ROI)**
วัชพืชที่อยู่ไกลจากหัวฉีดจะยังไม่สั่งพ่น รอจนรถเคลื่อนเข้ามาในระยะก่อน

**3. ยืนยันหลายเฟรม (Debounce)**
ต้องเจอวัชพืชติดกัน `confirm_frames` เฟรมจึงเริ่มพ่น และต้องไม่เจอติดกัน
`release_frames` เฟรมจึงหยุด กันการตรวจผิดเฟรมเดียวจากภาพเบลอ (Motion Blur)
ซึ่งเอกสารโครงงานระบุว่าเป็นความท้าทายหลักของงานนี้

**4. ป้องกันพืชหลัก**
ถ้ากล่องวัชพืชทับหรืออยู่ชิดกับกล่องพืชเป้าหมายภายในระยะ `protect_margin_px`
ระบบจะ **งดพ่น** เพื่อไม่ให้สารเคมีปลิวไปโดนพืชผลจนเสียหาย

**5. ระบบนิรภัย**
- `min_on_seconds` — พ่นแล้วต้องพ่นให้นานพอที่ยาจะออกจริง
- `max_on_seconds` — พ่นต่อเนื่องเกินเวลานี้ตัดทันที ไม่ว่ากรณีใด กันปั๊มค้างจนยาหมดถัง
- `cooldown_seconds` — พักก่อนพ่นรอบถัดไป
- ทุกทางออกของโปรแกรม (จบปกติ, `Ctrl+C`, error, `SIGTERM`) ปิดรีเลย์เสมอผ่าน `try/finally`

### สองโหมดการตัดสินใจ: ปกติ vs ผกผัน (Inverse)

| | โหมดปกติ (`inverse_mode: false`) | โหมดผกผัน (`inverse_mode: true`) |
|---|---|---|
| ต้องมีคลาสวัชพืชในโมเดล | ต้องมี | ไม่ต้องมี |
| ตัดสินใจจาก | กล่องวัชพืชแต่ละกล่อง (ทีละคู่กับพืชเป้าหมาย) | มี/ไม่มีพืชเป้าหมายในเขตพ่น (เช็คครั้งเดียวต่อเฟรม) |
| ภาระการประมวลผล | มากกว่า (ขยายกล่อง + เช็คซ้อนทับต่อคู่) | น้อยกว่า มาก เหมาะกับ Pi 4 (4GB) |
| ความละเอียด | พ่นเฉพาะจุดที่เป็นวัชพืชจริง | พ่นทั้งเขต ROI รวมถึงดินเปล่า/พื้นที่ว่างด้วย |
| ใช้เมื่อ | มีชุดข้อมูลวัชพืชคู่กับพืชหลัก | มีแค่โมเดลจำแนกพืชหลัก (เช่น ความสุกของสตรอว์เบอร์รี) ไม่มีคลาสวัชพืชแยก |

**โหมดผกผัน (Inverse / Crop-vs-Non-crop detection)** คือกลยุทธ์ "อะไรก็ตามที่ไม่ใช่
พืชเป้าหมาย ให้ถือว่าต้องพ่น" — ไม่ต้องสอนโมเดลให้รู้จักวัชพืชทุกสายพันธุ์
เหมาะมากเมื่อทรัพยากรจำกัด (Raspberry Pi 4 4GB) เพราะการตัดสินใจในเฟรม
เหลือแค่ "เจอพืชเป้าหมายในเขตพ่นหรือไม่" ตัวเดียว ไม่ต้องคำนวณ IoU/ระยะห่าง
เป็นรายคู่กล่องเหมือนโหมดปกติ — แลกมาด้วยการพ่นโดนดินเปล่าที่ไม่มีทั้งพืชหลัก
และวัชพืชไปด้วย (ยอมรับได้สำหรับงานกำจัดวัชพืชทั่วไป)

เปิดใช้งานที่ `classes.inverse_mode: true` ใน `config.yaml` — เมื่อเปิดแล้ว
`spray.protect_crop`/`protect_margin_px` จะไม่มีผล เพราะ "งดพ่นทั้งเขตเมื่อเจอ
พืชเป้าหมาย" ป้องกันพืชหลักเข้มงวดกว่าการเช็คระยะห่างเป็นรายกล่องอยู่แล้ว

ส่วน `classes.weed` **ไม่เปลี่ยนผลการตัดสินใจ** ในโหมดนี้ (ตัดสินจาก `classes.target`
อย่างเดียวเสมอ) แต่ถ้าตัวตรวจจับรู้จักคลาสวัชพืชจริง ระบบจะใช้กล่องวัชพืชเหล่านั้น
เป็น "ตำแหน่งเป้าหมาย" ที่บันทึกลง log และวาดลงภาพ แทนกรอบสังเคราะห์ที่คลุมทั้งเขต
— ได้ข้อมูลละเอียดขึ้นโดยผลลัพธ์ ON/OFF ยังเหมือนเดิมเป๊ะ กรณีนี้เกิดกับ
[โหมดต้นแบบนำเสนอผลงาน](#0-โหมดต้นแบบนำเสนอผลงาน-prototype-v1) ที่แผ่นสีเขียวเป็น

| ในเขตพ่น | ผลการตัดสิน | กรอบที่รายงาน |
|---|---|---|
| พบพืชเป้าหมาย | ไม่พ่น | กรอบพืชเป้าหมาย + `HOLD` |

เครื่องสถานะ (ใช้ร่วมกันทั้งสองโหมด — ต่างแค่ว่า "นับเป็นเป้าให้พ่น" จากอะไร):

### 6.1 เลเซอร์ KY-008 / HW-483 (prototype-v1)

#### ⛔ ห้ามต่อเลเซอร์เข้าขา GPIO ตรงๆ

นี่คือจุดที่ทำพลาดแล้วบอร์ดพัง อ่านให้จบก่อนต่อไฟ:

| | ค่า |
|---|---|
| ขา GPIO ของ Pi จ่ายได้ปลอดภัย | **~16 mA** ต่อขา (รวมทุกขาไม่เกิน 50 mA) |
| โมดูล KY-008 กิน | **~30-40 mA** |
| แรงดันขา GPIO | 3.3V |
| แรงดันที่โมดูลออกแบบมา | 5V |

ต่อตรงจึงผิดสองชั้น — **กระแสเกินพิกัดขา** (เสี่ยงทำให้ชิปเสียหายถาวร แบบค่อยๆ ตายไม่ใช่พังทันที
จึงมักไม่รู้ตัว) และ **แรงดันไม่พอ** (ได้แสงหรี่หรือไม่ติดเลย) ต้องมีทรานซิสเตอร์คั่นเสมอ

#### วงจรที่ใช้ — NPN low-side switch

```
Pi 5V (ขา 2) ──────────────► KY-008 ขา S  (สัญญาณ/ขั้วบวก)
                                   │
                             KY-008 ขา −  (กราวด์)
                                   │
                                   ▼
                            ┌──────────────┐
Pi GPIO17 (ขา 11) ──[1kΩ]──┤ B    C       │  ทรานซิสเตอร์ NPN
                            │   2N2222 /   │  (S8050, BC337, 2N3904 ก็ได้)
                            │   S8050      │
                            └──────┬───────┘
                                   │ E
Pi GND (ขา 6) ─────────────────────┴──────► GND ร่วม

เพิ่ม: ตัวต้านทาน 10kΩ คร่อมระหว่าง GPIO17 กับ GND (pull-down กันขาลอยตอนบูต)
```

| อุปกรณ์ | ต่อจาก | ต่อเข้า |
|---|---|---|
| KY-008 ขา `S` | — | Pi **5V** (ขากายภาพ 2 หรือ 4) |
| KY-008 ขากลาง | — | **ไม่ต่อ** (ดูหมายเหตุด้านล่าง) |
| KY-008 ขา `−` | — | ขา **C** (collector) ของทรานซิสเตอร์ |
| ตัวต้านทาน 1kΩ | Pi **GPIO17** (ขากายภาพ 11) | ขา **B** (base) ของทรานซิสเตอร์ |
| ตัวต้านทาน 10kΩ | Pi **GPIO17** | Pi **GND** |
| ขา **E** (emitter) | — | Pi **GND** (ขากายภาพ 6) |

หลักการ: Pi ไม่ได้จ่ายไฟให้เลเซอร์ แค่จ่ายกระแส ~3 mA เข้าขา B เพื่อ "สั่ง" ให้ทรานซิสเตอร์
ต่อวงจรฝั่งกราวด์ของเลเซอร์ ส่วนกระแส 30-40 mA ที่เลเซอร์ต้องการมาจากขา 5V ของบอร์ดโดยตรง
ซึ่งจ่ายได้สบาย

> **หมายเหตุขากลางของ KY-008**: บอร์ดแท้ขากลาง**ไม่ได้ต่ออะไร (NC)** แต่บอร์ดจีนบางล็อต
> สลับตำแหน่งขา ก่อนต่อให้เช็คด้วยมัลติมิเตอร์โหมดวัดความต่อเนื่อง: หาขาที่ต่อถึง**ขั้วลบ
> ของหัวเลเซอร์** — ขานั้นคือ `−` ที่ต้องเข้าคอลเลกเตอร์ ถ้าเช็คไม่ได้ ให้ต่อแบบ 2 ขาก่อน
> (`S` และ `−` เท่านั้น) ตามที่ตารางบอก แล้วปล่อยขากลางลอยไว้

#### ทางเลือกอื่น

| วิธี | ข้อดี | ข้อเสีย |
|---|---|---|
| **NPN + 1kΩ** (แนะนำ) | ของหาง่าย ราคาไม่กี่บาท ต่อครั้งเดียวจบ | ต้องต่อวงจรเอง |
| MOSFET 2N7000 / IRLZ44N | ไม่กินกระแสขา B เลย | ต้องเป็นชนิด logic-level เท่านั้น |
| **ใช้โมดูลรีเลย์เดิม** | ไม่ต้องต่ออะไรเพิ่ม แค่แก้ config | รีเลย์คลิกทุกครั้ง ตอบสนองช้า ~10 ms และเสียงดังตอนนำเสนอ |

ถ้ายังไม่มีทรานซิสเตอร์ ใช้รีเลย์เดิมไปก่อนได้: เอาสายเลเซอร์ต่อผ่าน `COM`/`NO`
แล้วตั้ง `relay.backend: auto` กับ `relay.active_high: false` ตามเดิม

#### ⚠️ `active_high` ต้องเป็น `true`

วงจร NPN แบบ low-side คือ **GPIO HIGH = เลเซอร์ติด** ถ้าตั้ง `false`
ขาจะถูกดึงเป็น HIGH ตอนพัก → **เลเซอร์ติดค้างตลอดเวลาตั้งแต่โปรแกรมเริ่ม**

```yaml
relay:
  backend: gpio        # ขับขาตรง ไม่มีรีเลย์คั่น
  pin: 17
  active_high: true    # ⭐ สำคัญที่สุด
  actuator: laser
  power: 1.0           # ลดเหลือ 0.3-0.5 ตอนสาธิตใกล้ผู้ชม (PWM)
```

โปรแกรมจะเตือนเองถ้าตั้ง `backend: gpio` คู่กับ `active_high: false` และมีเทสต์
[tests/test_laser_output.py](tests/test_laser_output.py) ล็อกค่านี้ไว้ไม่ให้ใครเผลอแก้กลับ

#### ทดสอบก่อนใช้งานจริงเสมอ

```bash
python tools/laser_test.py --dry-run    # 1. ดูลำดับคำสั่ง ยังไม่แตะ GPIO
python tools/laser_test.py              # 2. ยิงจริงสั้นๆ พร้อมคำเตือนความปลอดภัย
python tools/laser_test.py --sweep      # 3. ไล่กำลัง 20->100% ตรวจว่า PWM ทำงาน
```

ถ้า**จุดแดงติดตั้งแต่ขั้นที่ 1** ทั้งที่โปรแกรมยังไม่สั่งอะไร แปลว่าตั้ง `active_high` ผิดด้าน

#### 🔴 ความปลอดภัยของเลเซอร์

KY-008 เป็นเลเซอร์ 650nm ~5 mW (Class 3R) — **ทำให้ตาบาดเจ็บถาวรได้** ถ้าจ้องตรงๆ

- หันหัวเลเซอร์**ลงพื้นโต๊ะ**เสมอ หรือใส่กล่อง/กระดาษขาวรองไว้
- ห้ามหันเข้าหาคน สัตว์ **กระจก จอมอนิเตอร์ หรือของมันวาว** (แสงสะท้อนอันตรายพอกัน)
- ดู "จุดแดงบนพื้น" จากมุมเฉียง ห้ามมองเข้าไปในลำแสง
- กันผู้ชม/เด็กออกจากแนวลำแสงตลอดการสาธิต
- เตรียม**สวิตช์ตัดไฟจริง**ไว้ใกล้มือ — ปุ่ม `x` ในโปรแกรมคือหยุดฉุกเฉินในซอฟต์แวร์
  แต่สวิตช์จริงเชื่อถือได้มากกว่าเมื่อโปรแกรมค้าง
- ตั้ง `relay.power: 0.3` ตอนสาธิตในห้อง ยังเห็นจุดแดงชัดแต่กำลังเฉลี่ยลดลง
  (**ไม่ได้แปลว่าปลอดภัยแล้ว** ยังห้ามเข้าตาอยู่ดี)

### 6.2 โมดูลรีเลย์ 1 ช่อง (ระบบปั๊มพ่นยาตัวจริง)

| ขาโมดูลรีเลย์ | ต่อเข้ากับ Raspberry Pi | ขากายภาพ |
|---|---|---|
| `VCC` | 5V | ขา 2 |
| `GND` | GND | ขา 6 |
| `IN`  | GPIO 17 (BCM) | ขา 11 |

ฝั่งไฟแรงสูงของรีเลย์ (`COM` / `NO`) ต่อเข้ากับปั๊มน้ำและแหล่งจ่ายไฟของปั๊ม

โมดูลรีเลย์ราคาถูกส่วนใหญ่เป็น **Active LOW** (ส่งสัญญาณ 0 = รีเลย์ทำงาน)
ถ้าตั้ง `relay.active_high` ผิด **ปั๊มจะทำงานทันทีที่เปิดโปรแกรม**

**ทดสอบก่อนต่อปั๊มจริงเสมอ** โดยถอดสายปั๊มออกก่อน แล้วฟังแค่เสียงคลิกของรีเลย์:

```bash
python tools/relay_test.py --mock   # บน PC
python tools/relay_test.py          # บน Pi
```

ถ้าได้ยินเสียงคลิกตั้งแต่ตอนเริ่มโปรแกรม แปลว่าตั้งค่าสลับกัน ให้แก้ `config.yaml`

**ห้ามจ่ายไฟปั๊มจากขา 5V ของ Raspberry Pi โดยตรง** ต้องใช้แหล่งจ่ายไฟแยก
ไม่งั้นบอร์ดจะรีสตาร์ทตอนปั๊มเริ่มหมุน (กระแสกระชาก) และอาจทำให้ SD card เสียหาย

> ข้อนี้ไม่ใช้กับเลเซอร์ — KY-008 กินแค่ 30-40 mA จ่ายจากขา 5V ของบอร์ดได้สบาย

## 7. การติดตั้งบน Raspberry Pi

### 7.1 ติดตั้งสภาพแวดล้อม

คัดลอกโฟลเดอร์ `CODE/` ทั้งหมดไปที่ Pi แล้วรัน:

```bash
chmod +x scripts/setup_pi.sh
./scripts/setup_pi.sh
```

สคริปต์นี้ติดตั้ง `picamera2` และ `gpiozero` ผ่าน apt (ต้องผ่าน apt เท่านั้น pip ใช้ไม่ได้)
แล้วสร้าง virtual environment แบบ `--system-site-packages` เพื่อให้มองเห็นแพ็กเกจเหล่านั้น

**สังเกตว่าไม่มี ultralytics และ PyTorch** — เป็นความตั้งใจ เพราะกินพื้นที่กว่า 2 GB
และช้ามากบน Pi เราใช้แค่ `tflite-runtime` ขนาดไม่กี่ MB แทน

### 7.2 คัดลอกโมเดล

```powershell
# รันที่เครื่อง PC
scp models\best_float32.tflite pi@<ไอพีของ Pi>:~/CODE/models/
```

### 7.3 แก้ config.yaml บน Pi

```yaml
camera:
  source: picamera2

model:
  weights: models/best_float32.tflite
  num_threads: 4          # Pi 4 มี 4 คอร์

runtime:
  show_window: false      # ไม่มีจอต่ออยู่
```

### 7.4 ทดสอบทีละส่วนตามลำดับ

```bash
source ~/smartfarm-env/bin/activate

python tools/camera_test.py --source picamera2   # 1. กล้องเห็นภาพไหม ภาพคมพอไหม
python tools/relay_test.py                       # 2. รีเลย์ทำงานถูกต้องไหม (ถอดปั๊มออกก่อน)
python tools/benchmark.py                        # 3. ได้กี่ FPS
python -m src.main --headless                    # 4. รันระบบเต็ม
```

### 7.5 ให้ระบบทำงานอัตโนมัติเมื่อเปิดเครื่อง

มีไฟล์ template ให้แล้วที่ `scripts/smartfarm.service` — แก้ `User`/`WorkingDirectory`/`ExecStart`
ให้ตรงกับ username และ path จริงของเครื่องคุณก่อน (ค่าเริ่มต้นในไฟล์สมมติว่า username คือ `pi`)
แล้วคัดลอกไปที่ `/etc/systemd/system/`:

```bash
sudo cp scripts/smartfarm.service /etc/systemd/system/smartfarm.service
sudo systemctl daemon-reload
sudo systemctl enable smartfarm.service
sudo systemctl start smartfarm.service
sudo journalctl -u smartfarm.service -f      # ดู log แบบเรียลไทม์
```

**สำคัญ**: ไฟล์ template มี `Environment=PYTHONUNBUFFERED=1` ไว้แล้ว — ถ้าไม่มีบรรทัดนี้
`journalctl -f` จะไม่เห็น log สดเลย เพราะ Python จะ buffer ข้อความไว้ทั้งก้อนแทนที่จะพิมพ์
ทันทีเมื่อไม่ได้รันอยู่บน terminal จริง (ยืนยันจากการทดสอบ deploy จริง)

โปรแกรมจับสัญญาณ `SIGTERM` ไว้แล้ว เมื่อสั่ง `systemctl stop` ปั๊มจะถูกปิดอย่างเรียบร้อยเสมอ

## 9. ใช้โมเดลสำเร็จรูปจาก Roboflow (ทางเลือกไม่บังคับ)

โดยไม่ต้องมีไฟล์ `.pt`/`.tflite` ของตัวเอง เหมาะกับการทดสอบเร็วๆ หรือเทียบผล
ก่อนตัดสินใจเทรนโมเดลของตัวเอง

> ⚠️ **ใช้ทดสอบเท่านั้น ห้ามใช้ควบคุมปั๊มแบบเรียลไทม์บน Raspberry Pi จริง**
> เพราะต้องพึ่งอินเทอร์เน็ตตลอดเวลา และแต่ละภาพมี latency เครือข่ายเพิ่ม
> ~0.3-2 วินาที ทำให้ไม่ทันต่อการสั่งพ่นขณะรถเคลื่อนที่ ต่างจากเอนจิ้น
> `ultralytics`/`tflite` ที่ประมวลผลในเครื่องล้วนๆ (ดูรายละเอียดในตาราง
> เปรียบเทียบเอนจิ้นที่หัวข้อ [4. การตั้งค่า](#4-การตั้งค่า-configyaml))

### ทดสอบภาพนิ่งทีละภาพ

```powershell
pip install inference-sdk   # ติดตั้งครั้งเดียว (ดูข้อควรระวังเรื่อง Python ด้านล่าง)
```

ตั้งค่า API key — **ห้ามใส่คีย์ลงไฟล์ใดๆ ที่ commit เข้า git**:

```powershell
copy .env.example .env
# แล้วแก้ .env ใส่ ROBOFLOW_API_KEY=คีย์จริงของคุณ (ไฟล์ .env ถูกกันไว้ใน .gitignore แล้ว)
```

เอา API key ได้ที่ roboflow.com → ไอคอนรูปคน → **Settings** → **Roboflow API** → Private API Key

รันทดสอบ:

```powershell
python tools\roboflow_infer.py --image path\to\photo.jpg
python tools\roboflow_infer.py --image photo.jpg --save-annotated logs\annotated.jpg
python tools\roboflow_infer.py --image photo.jpg --model-id ชื่อโมเดล/เวอร์ชัน
```

### ใช้เป็น backend ที่สามใน src/main.py (ทดสอบ testbed แบบช้าๆ)

`model.backend: roboflow` ใน `config.yaml` ทำให้ `RoboflowDetector` เสียบเข้ากับ
ทั้งระบบ (ตรรกะพ่น, การวาดกรอบ, การบันทึก log) ได้ทันทีเหมือนอีก 2 เอนจิ้น
เหมาะกับทดสอบผ่าน `--source images` ที่เดินช้าๆ เท่านั้น:

```powershell
python -m src.main --source images --path datasets\test\images
```

### ⚠️ ข้อควรระวังเรื่อง Python 3.13

`inference-sdk` ยังไม่รองรับ Python 3.13 ในตอนนี้ (pip จะฟ้องว่าไม่มีเวอร์ชันที่ติดตั้งได้)
ถ้าเจอปัญหานี้ ให้สร้าง virtual environment แยกด้วย Python 3.10-3.12 สำหรับ
ขั้นตอนนี้โดยเฉพาะ เหมือนกับข้อควรระวังเรื่องการแปลง TFLite

### หมายเหตุเรื่องคลาสของโมเดลสำเร็จรูป

โมเดลสำเร็จรูปบางตัว (เช่น `strawberry-detection-msf0m/3`) อาจรู้จักแค่คลาส
`strawberry` อย่างเดียว ไม่มีคลาสวัชพืช ทำให้ตรรกะ "พ่นเฉพาะวัชพืช" ใน

สตรอว์เบอร์รีแม่นแค่ไหน ถ้าต้องการระบบแยกพืช/วัชพืชแบบเต็มรูปแบบ ยังต้อง
เทรนโมเดลของตัวเอง (ดูหัวข้อ [3. ขั้นตอนการพัฒนา](#3-ขั้นตอนการพัฒนาทั้ง-5-ขั้น))

3. ตรวจว่าชื่อใน `color.red_name` ตรงกับที่อยู่ใน `classes.target` เป๊ะๆ
   (ถ้าไม่ตรง โปรแกรมจะพิมพ์คำเตือน `[detector] เตือน: ชื่อสีในหมวด color...` ตอนเริ่ม)
4. แผ่นสีเล็กเกิน `color.min_area_frac` หรือเปล่า — ลองขยับเข้าใกล้กล้อง

### โหมดสี: เจอสีมั่วไปหมด / พื้นหลังกลายเป็นวัตถุ
เพิ่ม `color.*_sat_min` ทีละ 10 จนพื้นหลังเงียบ (นี่คือค่าที่ได้ผลที่สุด — สีจริงสด
แต่ผนัง/เงา/ผิวคน "จืด") ถ้ายังไม่พอค่อยเพิ่ม `*_val_min` และบีบช่วง `*_hue_ranges` ให้แคบลง
ระวังพื้นไม้และผิวคนเป็นพิเศษ เพราะมี hue ใกล้เคียงสีแดง

### โหมดสี: เลเซอร์กะพริบเป็นจังหวะทั้งที่ฉากไม่เปลี่ยน
เป็นระบบกันทำงานค้างที่ตัดตาม `spray.max_on_seconds` แล้วพักตาม `cooldown_seconds`
ตามการออกแบบ — ยืด `max_on_seconds` ถ้าต้องการให้ยิงต่อเนื่องนานขึ้นระหว่างสาธิต
(branch นี้ตั้งไว้ 30 วินาทีแล้ว) แต่**อย่าถอดกลไกนี้ออก** และตั้งกลับเป็น 5.00 เมื่อคุมปั๊มจริง

### `RuntimeError: รูปร่างเอาต์พุตของโมเดลไม่ตรงกับจำนวนคลาส`
`classes.names` ใน config.yaml ไม่ตรงกับจำนวนคลาสที่ใช้ตอนเทรน
เปิด `datasets/data.yaml` ดูค่า `names` แล้วคัดลอกมาใส่ให้ตรงกัน

### แปลง TFLite ไม่สำเร็จบน Windows / Python 3.13
สายการแปลง (`onnx2tf`, `tensorflow`) ยังมีปัญหาความเข้ากันได้กับ Python 3.13
ใช้ [notebooks/train_smartfarm_colab.ipynb](notebooks/train_smartfarm_colab.ipynb) แทน
โน้ตบุ๊กนี้แปลงให้ทั้ง float32 และ int8 พร้อมตรวจสอบไฟล์ที่ได้ว่าใช้กับโค้ดฝั่ง Pi ได้จริง

### เทรนแล้วแต่ Colab บอกว่าหาภาพไม่เจอ
ไฟล์ `data.yaml` ที่ Roboflow สร้างมาใช้พาธแบบ `../train/images` ซึ่งชี้ผิดที่บน Colab
เซลล์ "ขั้นที่ 3 — ตรวจสอบและซ่อมชุดข้อมูล" ในโน้ตบุ๊กจะเขียนพาธใหม่ให้อัตโนมัติ
ต้องรันเซลล์นั้นก่อนเซลล์เทรนเสมอ

### โมเดลตรวจจับผิดบ่อย (พ่นทั้งที่ไม่ใช่วัชพืช)
1. เพิ่มเกณฑ์ความเชื่อมั่น: `classes.per_class_conf.weed: 0.65`
2. เพิ่มจำนวนเฟรมที่ต้องยืนยัน: `spray.confirm_frames: 5`
3. หาค่าที่เหมาะที่สุดด้วยข้อมูลจริง: `python tools\evaluate.py`
4. เก็บภาพพื้นหลังที่ไม่มีวัตถุ (label ว่าง) เพิ่มในชุดข้อมูลราว 5-10%
